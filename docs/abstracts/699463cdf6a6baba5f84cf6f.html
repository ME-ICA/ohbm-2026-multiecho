Introduction

CBRAIN ^1 (https://cbrain.ca) is an open source, web-based, collaborative research software platform designed to address major challenges in big data research. CBRAIN allows scientists to launch large-scale big data analyses using advanced scientific tools through an easy to use web-based user interface, removing the steep learning curve and pitfalls associated with a complex command-line environment. CBRAIN makes available over 160 pre-configured analysis pipelines for neuroimaging and genetics. This includes scientific tools for single-cell transcriptomics such as scRNAbox ^2, a single-cell RNA sequencing (scRNAseq) pipeline, and most recently Ensemblex ^3, an accuracy-weighted ensemble framework for genetic demultiplexing of pooled scRNAseq data.

As new scientific tools and pipelines are being developed, the capability to seamlessly integrate them in CBRAIN is crucial. The process to integrate new tools has been streamlined and uses Boutiques ^4 to define the command line and tool parameters in a JSON format. The use of Boutiques offers multiple parameter validation features and enables clearer form validation messages. Based on the descriptor, CBRAIN automatically builds the user interface for each tool allowing users to select application parameters while automatically performing parameter validation. Containers, namely Docker and Apptainer ^5, are used to encapsulate the tool.

Occasionally, the integration of the tool in CBRAIN via Boutiques descriptor requires additional programming steps to define custom modules that will be used by the CBRAIN framework. To integrate Ensemblex into CBRAIN, custom Boutiques modules were used.

Methods

The Ensemblex pipeline can be used to demultiplex pools of scRNAseq data with or without prior genotype information. When demultiplexing with (or without) prior genotype information, Ensemblex leverages the sample assignments of four individual, constituent genetic demultiplexing tools:

When demultiplexing with prior genotype information, pipeline executes the following constituent demultiplexing tools ^3: Demuxalot, Demuxlet, Souporcell and Vireo-GT.

When demultiplexing without prior genotype information, the pipeline executes the following set of constituent tools ^3: Demulxalot, Freemuxlet, Souporcell and Vireo.

Using demultiplexing pools with each of the respective set of four genetic demultiplexing tools, Ensemblex processes the output files in a three-step pipeline (see Figure 1) to identify the most probable sample label for each cell based on the predictions of the constituent tools:

Step 1: Probabilistic-weighted ensemble

Step 2: Graph-based doublet detection

Step 3: Ensemble-independent doublet detection

As output, Ensemblex returns its own cell-specific sample labels and corresponding assignment probabilities and singlet confidence score, as well as the sample labels and corresponding assignment probabilities for each constituent. The demultiplexed sample labels could then be used to perform downstream analyses.

To integrate the Ensemblex pipeline in CBRAIN, a wrapper was created to prepare the input files, including the creation of a config file that contains a summary of variables and options needed for the pipeline execution.  The wrapper also makes use of the CBRAIN integration methods that allow all additional dependencies, such as genomics reference files, to be packaged alongside the tool container, avoiding any unnecessary data duplication via downloads at runtime.  Such downloads at runtime are also typically not permitted by the security policies of HPC resource centres where such tools would be run.

The integration of Ensemblex also addresses the issue of input management. In Ensemblex the tool mutates the input given to the pipeline by adding the output to the input given by the previous step. This behaviour can lead to issues in CBRAIN if multiple tasks are run on the same input data. CBRAIN and the Boutiques integration ensures that each task from the perspective of CBRAIN works with the necessary unmodified data inputs, avoiding any mutation or overwriting of input data by other tasks.

Results

To solve the input management problem a Boutiques custom module called ‘BoutiquesInputCopier’ (previously developed for the scRNAbox integration in CBRAIN) was used. This module allows the creation of a full copy of the input before starting the tool. 

In the case of Ensemblex, the copy is always performed. However, the creator of the Boutiques descriptor can add an option to make this feature selectable in the form, allowing the user to avoid the extra copying step, if desired, for other tool integrations.

With the integration of Ensemblex into CBRAIN, users are able to perform all these steps through the CBRAIN web interface, specifying all input parameters through either selection from a pre-populated drop-down menu, or through a check-box mechanism (see Figure 2), avoiding the risk of errors in specifying such parameters and tool options via the command-line.  Furthermore, CBRAIN records the provenance of all data managed and created through pipeline executions, maintaining the relationship information between input data, the processing tool and the generated derived data.  This automated record keeping eliminates the need for users to manually store and record the provenance information, which can be inefficient, time consuming and error prone.

Conclusion

The integration of Ensemblex into CBRAIN demonstrates the flexibility and extensibility of integrating tools using the Boutiques framework. To address the challenges posed by tools such as Ensemblex and others, custom but generalizable Boutiques modules were used to manage input data, verify input data type and to set the output file type, ensuring efficient and reliable execution of the pipeline.

With the integration of Ensemblex into CBRAIN, users are able to avoid the pitfalls of working with scientific tools through the command-line, which can present a significant learning curve for researchers and subsequently result in error prone execution of the tool.  By integrating Ensemblex and other tools in CBRAIN, all the steps of specifying data management and input tool input parameters are instead done through the CBRAIN web interface, through either selection from a pre-populated drop-down menu, or a check-box mechanism. Furthermore, CBRAIN automatically records the provenance of all data managed and created through pipeline executions, eliminating the risks associated with laborious manual recording and storage of provenance information and logging
