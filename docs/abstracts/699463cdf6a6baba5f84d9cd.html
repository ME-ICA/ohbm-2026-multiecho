Introduction

Neuroimaging pipelines require tool interfaces for multiple workflow engines, dataset managers, and execution environments. The community has independently developed complementary solutions: BIDS standardizes data organization with emerging specifications for mapping tool outputs back to the standard, Pydra provides dataflow orchestration with its own interface system and provenance tracking, Neurodesk delivers validated containerized environments, Nipoppy offers BIDS-compliant dataset organization with provenance tracking, and NiWrap provides comprehensive tool metadata with multi-language interface generation. Each addresses part of the problem, and each of these initiatives addresses other pieces of the puzzle out of necessity. The independent development of these efforts has led to significant duplication of interface implementations and provenance systems, which is most concerning when it leads to inconsistent behaviors of neuroimaging tools, and in fact increases barriers to interoperability. We present a collaborative integration that unifies these efforts by establishing shared tool interface foundations that reduce maintenance burden while improving tool access for all users.

Methods

The integration centers on Boutiques descriptors as a common specification format, extended by NiWrap to support complex subcommand structures. A compilation pipeline transforms these descriptors into platform-specific interfaces: Styx backends generate type-safe wrappers for Python, TypeScript, and other languages, while a new Pydra backend produces workflow engine task interfaces directly from the shared descriptors. Neurodesk provides container infrastructure with these descriptors embedded directly, enabling systematic validation across tool versions. Nipoppy consumes NiWrap-generated Boutiques descriptors for pipeline execution, while contributing upstream ongoing improvements identified through cross-platform testing. Pydra's new Lmod support enables workflows to use Neurodesk software packages directly. BIDS maintainers are developing a term mapping specification (BEP) that defines how tool outputs map back to BIDS structure, which will be integrated into the Boutiques tool descriptors and would enable all described tools to automatically produce BIDS-compliant derivatives. Validation includes functional testing with standard neuroimaging workflows, cross-platform consistency testing, and deployment of reference implementations including a QSMxT-Nipoppy integration demonstrating end-to-end use.

Results

The integration provides immediate benefits across platforms. Pydra gains access to NiWrap's comprehensive tool interface collection through the new Styx backend, complementing its existing interface system while reducing manual reimplementation. Lmod support enables Pydra workflows to transparently use Neurodesk containers. Neurodesk's container integration with NiWrap provides systematic testing infrastructure that identifies interface issues benefiting all platforms. Nipoppy leverages NiWrap-generated Boutiques descriptors for pipeline integration. The extended Boutiques standard better captures complex tool interfaces while maintaining backward compatibility. Planned integration with the BIDS term mapping specification would further extend this: tools described in Boutiques could automatically map their outputs to BIDS derivatives structure. The collaborative model demonstrates sustainability: bug reports and improvements from cross-platform testing benefit all users, shared descriptor maintenance reduces duplicated effort, and improvements propagate automatically to all participating platforms.

Conclusion

This collaboration establishes shared infrastructure for neuroimaging tool access by coordinating development across BIDS, Pydra, Neurodesk, Nipoppy, and NiWrap. By compiling shared Boutiques descriptors into platform-specific interfaces, we reduce duplicated work while preserving and emphasizing each platform's unique capabilities. Working implementations demonstrate feasibility, and early community participation validates the collaborative model. The integrated platform is openly available, inviting continued community participation.
