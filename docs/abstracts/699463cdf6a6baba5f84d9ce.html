Introduction

CBRAIN^1 is an open-source, web-based distributed computing platform that enables collaborative neuroimaging research by managing data access and transfer, provenance, and the execution of analysis pipelines on HPC and cloud resources. While CBRAIN’s web portal supports many common workflows, advanced users often need programmatic access to list and query resources, integrate CBRAIN operations into scripts, and interact with CBRAIN from headless or remote terminal environments. We developed an open-source command-line interface (CLI), “cbrain-cli”, implemented in Python, to expose common CBRAIN operations via a single terminal command (“cbrain”) and a set of subcommands aligned with core CBRAIN entities. The tool was tested against the McGill CBRAIN portal instance (https://portal.cbrain.mcgill.ca/).

Methods

The CLI is implemented in Python using only standard libraries and provides a command-and-subcommand interface consistent with common Unix conventions ^2. The CLI groups operations by CBRAIN “models” (e.g., file, project, tool, task) and supports frequent inspection and navigation operations (e.g., listing resources, showing a specific resource by identifier, switching project context). Outputs can be rendered in human-readable form or in machine-readable formats (JSON or JSON Lines) to support scripting and downstream processing. The CLI is currently distributed in “clone-and-run” form as described in the project README. Development and testing were performed using Python 3.11 on macOS and Linux. Authentication is token-based via the CBRAIN REST APIs.

Results

The current CLI provides top-level commands for authentication/session inspection, plus model-specific command groups for common CBRAIN objects including files, projects, data providers, tools, tool configurations, tasks, background activities, remote resources, and tags. 

The README includes worked examples demonstrating typical interactive use such as switching a project, inspecting tools and data providers, and listing or showing items across multiple models. 

Optional JSON/JSONL output enables incorporation into shell pipelines and reproducible scripts that need structured results rather than manual interaction through a browser. These features support scripted workflows such as enumerating files within a project, selecting tools and tool configurations, submitting tasks from structured parameters, and tracking asynchronous background activities from a headless environment. Conclusion

A lightweight CLI complements the CBRAIN web portal by enabling terminal-first, scriptable interaction with CBRAIN resources and metadata, including structured outputs suitable for automation. This approach supports reproducible operational workflows (e.g., scripted inspection, querying, and tracking of tasks and background activities) while leveraging CBRAIN’s existing access controls and REST APIs. Ongoing development will expand documentation and examples and broaden endpoint coverage as user needs evolve.
