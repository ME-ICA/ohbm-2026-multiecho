Introduction

Systemic physiological processes, once primarily regarded as confounding noise in fMRI studies, are increasingly recognized as valuable signals linked to cognitive processes and individual differences in brain function1. Concurrent recordings of peripheral physiology—such as cardiac, respiratory—can enhance fMRI analysis through improved noise modeling and provide complementary insights into brain-body interactions. However, the utility of physiological data is contingent upon recording quality and expertise in data handling.

Quality assessment (QA) of physiological signals presents challenges distinct from established neuroimaging QA pipelines. Unlike fMRI, where automated tools such as MRIQC2 have standardized quality evaluation through image quality metrics and visual reports, no comprehensive solution exists for concurrent physiological recordings. While valuable tools exist (such as PhysIO2 and AFNI's physio_calc.py3), their focus is primarily on downstream processing rather than systematic physiological signal quality assessment and correction. Current QA practices for physiological data remain largely manual, time-consuming, and subject to considerable inter-rater variability. This inconsistency poses significant obstacles for large-scale studies and data sharing initiatives where standardized quality control is essential.

To address this gap, we introduce PhysAI/QA, a full-stack application designed for rapid, interactive, and standardized quality assessment of physiological signals in neuroimaging research (Fig. 1). Developed as part of the PhysAI research suite, this platform aims to streamline QA workflows for BIDS-compliant physiological data while minimizing human effort and error through integration of machine learning approaches. PhysAI/QA is designed to provide automated metrics, interactive visualization, and standardized reporting specifically tailored for various physiological modalities commonly acquired during neuroimaging experiments.

Methods

PhysAI/QA is implemented as a full-stack web application using Vue.js with D3.js for the frontend interface and FastAPI for the backend infrastructure (Fig. 1). The frontend provides component-based architecture with reactive data binding and hot module replacement during development. Data visualization capabilities integrate D3.js within Vue components using lifecycle hooks and reactive watchers, enabling responsive, interactive visualization while maintaining efficient data processing capabilities. Docker containerization ensures streamlined deployment and reproducibility across computing environments.

BIDS Integration and Data Loading: The platform begins with a guided workflow for connecting to any BIDS-compliant dataset. Upon specifying the dataset directory, PhysAI/QA automatically parses BIDS sidecar JSON files to detect available physiological signal types (e.g., cardiac, respiratory, trigger). This eliminates manual configuration and ensures accurate metadata extraction i.e. sampling frequencies, column specifications, and temporal alignment parameters. Additionally, a DataLad info-panel provides the instructions for accessing public neuroimaging datasets, enabling users to install and retrieve BIDS-compliant public data.

Multimodal Signal Discovery: Upon selecting a physiological signal(s) of interest, the application scans sibling directories and related functional runs to identify available auxiliary signals—including motion parameters from fMRIPrep outputs, stimulus event files, and additional physiological channels from the same recording session. Vue.js reactive state management coordinates signal construction, where each discovered file is processed into a normalized time series with sampling rates aligned across modalities. Additionally, PhysAI/QA supports user-defined derived signals (Fig. 2 - top row right panel). Built-in derivation functions include Heart Rate (HR), Respiration Volume (RV), and Global Signal (GS); users can define additional metrics via custom JavaScript methods or import externally computed values from tabular files, enabling flexible integration of domain-specific analyses.

Interactive Visualization Interface: The core visualization module provides intuitive signal exploration through D3 in the timeSeriesChart component encapsulated in Vue's reactivity system, optimized for real-time physiological signal updates. Component data flow follows Vue's unidirectional pattern with props for parent-to-child components and event emissions for state changes, enabling simultaneous multi-modal signal rendering of multiple signal modalities while maintaining responsive interaction with large datasets. Users can zoom, pan, and scroll through physiological time series to inspect data quality at multiple temporal scales (Fig. 2 - bottom panel). The linked view feature supports brush selection that highlights corresponding time windows across all displayed signals.

Backend Architecture: The backend is a RESTful API using FastAPI with Pydantic models for automatic request validation and type-safe input/output schemas. The modular structure organizes endpoints by functional domain—BIDS metadata parsing, signal preprocessing, quality metric calculation, and artifact detection—with POST endpoints accommodating complex parameter sets for sampling rates, filtering, and temporal alignment constraints.

Scalability and Extensibility: A stateless client-server design separates computationally intensive signal processing from visualization, enabling independent scaling of analysis pipelines. Asynchronous request handling manages I/O-bound operations efficiently while maintaining responsive API performance. This architecture supports incremental development of specialized quality metrics for emerging physiological modalities, allowing community contributions of domain-specific algorithms while maintaining backward compatibility with existing visualization components through clear Pydantic interface contracts.

Results

We present the current implementation status and preliminary capabilities of PhysAI/QA.

BIDS Parsing Validation: Testing across multiple publicly available OpenNeuro datasets (ds000210, ds006644, cneuromod friends) confirms reliable detection and loading of physiological signals from BIDS-compliant datasets. The system correctly interpreted metadata from JSON sidecar files and successfully identified cardiac (pulse oximetry, ECG), respiratory (belt, CO2), and trigger channels across all tested datasets.

Multimodal Integration: The platform successfully renders physiological signals simultaneously with experimental events (e.g., stimulus onsets, responses) and motion parameters (e.g., framewise displacement, DVARS), enabling identification of artifact-inducing periods and their potential impact on associated fMRI analyses. The coordinated multi-signal display enables researchers to distinguish true physiological responses from (e.g. motion-induced artifacts), and to evaluate whether physiological signal variability coincides with critical experimental events, which could compromise fMRI analysis validity.

Open Development: PhysAI/QA will be made publicly available and developed as open-source software to encourage community contribution and ensure broad accessibility for the neuroimaging community.

Conclusion

PhysAI/QA addresses a critical gap in the neuroimaging quality assessment landscape by providing integrated multimodal visualization and interactive capabilities specifically designed for physiological signals. While tools like MRIQC have transformed quality control practices for MRI data, concurrent physiological recordings have lacked equivalent infrastructure, leading to inconsistent practices and potential data quality issues across studies. Our aim is to support the growing recognition that physiological recordings contain valuable information beyond noise characterization, warranting quality standards commensurate with neuroimaging data. 

The current visualization and annotation interface enables researchers to contextualize physiological signal quality within the broader experimental timeline—overlaying multiple signals of interest with auxiliary signals to identify whether artifacts coincide with critical acquisition periods. Annotation capabilities enable researchers to flag artifact periods, mark signal quality ratings, and document observations that persist with the dataset, facilitating consistent QA practices across sessions and studies. This integrated approach reduces the friction of switching between disparate tools and provides a unified environment where physiological signal quality can be evaluated with the same rigor applied to neuroimaging data.

Future development priorities include (Fig. 1): (1) Dual-Stream Quality Assessment Architecture: At the core of our vision lies a dual-stream assessment paradigm integrating: manual expert review through the interactive interface, and machine learning-based classification and outlier detection. These streams will interact synergistically—automated ML annotations will highlight potential quality issues to guide expert inspection, while expert feedback will provide training signals for continuous model improvement. This human-in-the-loop approach will balance the reliability of expert judgment with the efficiency and consistency of automated methods. (2) Standardized QA Reporting: Following the paradigm established by MRIQC for neuroimaging data, we plan to implement standardized QA reports containing dataset metadata and acquisition details, visualizations of raw and derived signals (e.g., peak detection overlays, power spectra), and baseline quality metrics providing immediate overview of recording quality. Reports will facilitate both individual session review and aggregate dataset-level quality summaries. (3) Artifact Correction Pipeline Integration: When artifacts are identified as potentially correctable, PhysAI/QA will interface with specialized artifact correction tools. Planned integrations include in-house deep learning approaches for physiological signal reconstruction, and foundation model architectures specifically designed for physiological artifact correction (such as PaPaGei5). This modular design will allow incorporation of emerging correction methods as the field advances.
