Introduction

Conducting neuroimaging studies typically requires several steps that rely on different tools, which can hinder the reproducibility of experiments. Clinica (www.clinica.run) is an open-source neuroimaging software designed to ease the reproducibility of processing steps.1 It relies on the Brain Imaging Data Structure2 (BIDS) for input dataset organization and a BIDS-like structure for organising processing results. Clinica includes data management tools, mainly to convert raw public datasets to BIDS, and several processing and analysis pipelines for neuroimaging data (T1w, FLAIR, PET, diffusion MRI). 

Community adoption of the BIDS specification has improved neuroimaging data standardization and many tools now follow that standard, whether it is for quality control, processing or extraction of data. However large-scale, multi-cohort studies remain unequal in terms of processing pipelines and derivative organization, which undermines reproducibility.3 Clinica provides standardized converters and pipelines which can be applied one after the other on a folder. Still, connecting these to population-level analyses incorporating several processing steps and diverse metadata requires an additional layer of orchestration.

Nipoppy (https://nipoppy.readthedocs.io/en/latest/) is an open-source software providing a framework to standardize and track data processing on a study scale. It manages the structure of the data and the orchestration of processes. It itself does not provide processing tools but relies on external software tools that are invoked through its built-in machinery and referenced in a catalog.

Using Nipoppy should allow bridging this gap for easily managing studies involving several pipelines of Clinica. Here we present the addition of Clinica’s bids-converters and preprocessing pipelines to their catalog.

Methods

Clinica provides dataset-to-bids converters that organize raw data into a BIDS dataset (Figure 1A), for the following public datasets : ADNI, AIBL, GENFI, HABS, IXI, OASIS1, OASIS3, NIFD, UKBiobank. It also provides preprocessing and extraction pipelines of varying complexity, taking BIDS as an input and producing BIDS-like derivatives named ClinicA Processed Structure (CAPS) (Figure 1B). All tools are usable with a command line.

If containerized, converters can be used in Nipoppy at the conversion to BIDS (bidsification) step, while other pipelines can be used at the processing and extraction steps. Docker (https://www.docker.com/) was chosen for containerization. It is an open-source tool allowing the deployment of applications along with all the required dependencies in a container separate from the host machine. From the user point of view, executing an application through a container improves reproducibility and simplicity of use. 

We aim to share all Clinica converters and pipelines through Nipoppy. Among all tools provided by Clinica, containerization began with ixi-to-bids and t1-linear as they are the smallest and simplest converter and pipeline, respectively. ixi–to-bids converts the raw IXI (https://brain-development.org/) dataset into the BIDS format. t1-linear performs bias field correction, affine registration to the ICBM 2009c nonlinear symmetric template using ANTs and cropping of T1-weighted MR images. Both can be run without any third party software, only with Clinica and its Python dependencies, which make them easier to build inside a container. 

Once the blueprint (or image) for Docker containers is built and successfully yields functional outputs, it can be publicly released onto DockerHub. Aside from a container, Nipoppy also requires additional configuration files describing default parameters and fostering reproducibility. They describe the study at a general level and each step of a process, which can be bidsification, processing or extraction. Example configuration files from Nipoppy have to be tailored for each pipeline or converter in order for them to be executed by the framework. Configuration files can be shared with Zenodo (https://zenodo.org/) to be made available to all. With both the container and configuration files, a pipeline can be integrated to Nipoppy’s catalog.

Results

Both the ixi-to-bids converter and the t1-linear pipeline have been containerized. We demonstrate how to perform BIDS conversion and T1-weighted image preprocessing by using the combined framework of Nipoppy with containerized Clinica tools.

Once tools are available with Docker and Nipoppy, there is no need to install Clinica anymore to use them. With Nipoppy, the user can simply search its catalog and they will be guided through installing the right Docker image and configuration files for the pipeline. 

To use the ixi-to-bids converter, raw data should be placed into the imaging and tabular source data folders, then the converter can be installed and run (Figure 2). To use the t1-linear pipeline, either the converter should be installed beforehand or the BIDS should be copied into the right folder. Then, the pipeline can be installed and run. Built-in tools for checking status can be run to see dataset processing completion.

Containerization of all Clinica tools is just the beginning. Thanks to the help and reactivity of the people behind Nipoppy, so far it has been possible to containerize the simplest BIDS converter and pipeline of Clinica. 

Conclusion

Together, Nipoppy and Clinica offer a reproducible and fully standardized ecosystem for large-scale neuroimaging analysis. This enables cross-cohort harmonization and facilitates machine and deep learning applications. We intend on continuously expanding Nipoppy’s catalog with other available Clinica pipelines. 

Users of Clinica that do not use Nipoppy also benefit from containerized pipelines, though the use of this workflow is recommended for standardization purposes and growth within the neuroimaging community.
