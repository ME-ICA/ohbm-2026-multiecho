Introduction

CBRAIN^1 is an open-source, web-based platform that enables collaborative neuroimaging research. It allows scientists to launch, monitor, and share large-scale analyses using advanced tools through an intuitive interface. Traditionally, CBRAIN mostly relies on academic HPC clusters in Canada, with limited support for selected overseas resources. Commercial cloud computing offers flexibility, scalability, reliability and availability, not to mention increasingly sought after graphical and dedicated machine learning hardware. As early as 2014 the CBRAIN team incorporated AWS EC2 ^2. Our early approach relied on AWS API, and required dedicated Virtual Machines for each scientific tool, which was adequate, as at that time CBRAIN supported significantly fewer tools than now. Those early cloud integration attempts were abandoned due to cost and maintenance challenges. AWS S3 is still being used frequently on CBRAIN, though more often with Open Source analogues than Amazon proper resources.  

Occasionally, Magic Castle ^3, a virtual environment emulating Digital Research Alliance (the Alliance) clusters and SLURM on major cloud providers, was used for training and demonstrations of CBRAIN. Magic Castle works great for training. Yet potential CBRAIN users interested in cloud resources deem it too heavy for any usage at scale.

Google Cloud Platform (GCP) ranks among the top cloud providers, following the market leader AWS and the enterprize-oriented Azure. A recent comparative study reveals that while not necessarily offering the best CPU, GPU, network and memory performance,  Google Cloud excels in cost efficiency for sustained load ^4, and is geared toward Machine Learning and Open Source ecosystems.

Integrating GCP into CBRAIN enables broader access to cloud resources for neuroimaging pipelines. In collaboration with the Digital Research Alliance of Canada we integrated Google Cloud BATCH service, intended to run scientific workloads.

Methods

CBRAIN is a distributed system composed of one or more web portals and heterogeneous execution agents. On HPC clusters, agents are installed on login nodes. For GCP, we defined three Virtual Machine images (VMs): one for executing BATCH jobs, similarly to cluster compute nodes, one for distributed storage, and one for CBRAIN agents that monitors the execution of tasks on cloud side autonomously. The present integration relies on the Apptainer container engine which is favored in academic settings, for which we had to define as the container solution to use in the corresponding VMs, as GCP and other commercial cloud services are more geared toward Docker. The execution VM instances are ephemeral, low-cost preemptive machines that exist only during task execution.

Several persistent disks were provisioned, with the largest intended for caching data and working task directories as shown on the figure below. 

CBRAIN’s Simple Cluster Interface Ruby (SCIR) library bridges portals with job schedulers such as SLURM and Torque on HPC clusters, and was extended to support GCP Batch. 

GCP Batch is a lighter-weight solution than SLURM with the trade-off that GCP Batch does not presently support Message Passing Interface (MPI).

This allows tasks to be scheduled and executed efficiently in the cloud while maintaining reproducibility and monitoring capabilities. We rely on the GCP command-line interface for job submission, as all other SCIR use command-line scheduling tools rather than API.

Results

GCP Batch was successfully integrated with CBRAIN and tested on several popular neuroimaging pipelines, including Hippunfold, FreeSurfer and DeepPrep. Tasks executed on ephemeral VM instances demonstrating that large pipelines can run in parallel without dedicated HPC infrastructure, and integration with persistent storage ensured efficient data management. Users are able submit, monitor, and retrieve results via the CBRAIN web portal, with GCP resources dynamically allocated and released upon task completion. Since the GCP Batch service is very similar to the Batch service offerings of competing cloud platforms, the intention is to add support in CBRAIN for Batch integration from other cloud platforms such as AWS and Azure, in an upcoming CBRAIN release.

Conclusion

CBRAIN now supports GCP via Google Cloud Batch, enabling scalable, secure, and reproducible neuroimaging workflows. This integration reduces reliance on HPC clusters, expands access to modern cloud hardware, and simplifies deployment of large-scale analyses. Future work will focus on deeper integration with Cloud Batch features, performance optimization, and broader support for additional scientific pipelines.
