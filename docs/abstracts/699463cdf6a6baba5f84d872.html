Introduction

Nilearn is a Python package designed to simplify statistical analysis and machine learning on neuroimaging data. Built upon the scikit-learn API1, it provides high-level tools for general linear modeling (GLM), decoding, connectivity analysis, and last but not the least, visualization of brain images. With over a decade of sustained development, more than 200 contributors, and over 3000 citations2, Nilearn has become a core component of the open-source neuroimaging scientific ecosystem. Given how vital data visualization is for scientific communication, we believe that it is Nilearn’s plotting features that make it indispensable for any MR image analysis workflow. So it is no surprise that the plotting sub-module of Nilearn is the most imported part of the package.3 This observation has driven us to add new plotting features and improve existing visualization tools in recent releases of Nilearn.

On top of visualization, Nilearn v0.11.1 addressed key issues introduced during the initial surface data support. Subsequent releases 0.12.0 and 0.12.1 extended surface compatibility across image manipulation, masking, statistical inference, and reporting. These releases also continue the work towards better alignment with scikit-learn’s estimator guidelines, ensuring that advanced neuroimaging workflows remain reliable, reproducible, and interoperable.

Finally, the 0.13.0 release prioritizes long-standing deprecations, large-scale API cleanup, and modernization of supported dependencies. This effort prepares the library for a more stable, predictable future, particularly for users relying on automated pipelines, teaching materials, and long-term research projects.

Methods

Nilearn follows a documentation-driven and community-centered development model. Its user guide, example gallery, and reporting system are tightly coupled to the underlying API, ensuring that new functionality remains discoverable and usable.

As mentioned previously, the plotting sub-module of Nilearn is the most imported part of the package (Figure 1). Therefore, the new visualization features are designed to meet the needs of the neuroscientific community. Recent work has emphasized the importance of transparent thresholding4 and Bland-Altman comparisons5 in neuroimaging analyses, both of which can now be natively done via Nilearn. Moreover, outside of the plotting module, we have improved the reports generated by various Nilearn objects (namely, the maskers and first-level and second-level GLM objects). These include support for dual-hemisphere plotting in surface reports, consistent metrics and visualizations, improved lookup-table handling, improved layout and thresholding logic in visualization in GLM reports, and more warnings to indicate potential issues specific to the input data.

Furthermore, particular attention was given to harmonizing behavior across volume and surface workflows, including consistent data typing, shape guarantees, and reporting outputs. Surface methods were extended across image operations (e.g., computing mean, concatenating, thresholding, confound regression), GLM workflows, and non-parametric inference.

Releases v0.12.0–0.12.1 introduced extensive internal refactoring to improve estimator compliance with scikit-learn. Public attributes whose modification could lead to inconsistent estimator states were removed in favor of standardized estimator tags, while new fitted attributes were added to mirror scikit-learn conventions.

Results

Nilearn continues to show steady adoption within the neuroimaging community, with over 1,300 GitHub stars, 600 forks, and integration into more than 200 dependent packages.

Functionally, Nilearn now offers near-feature parity between volumetric and surface-based analyses. All major modules, including masking, GLM estimation, decoding, reporting, and visualization, support surface data through a unified API. Surface-based GLMs can now generate interactive HTML reports and be saved in BIDS-compatible formats.

Maskers and image manipulation modules now have more consistent variable names for input and output. Deterministic atlases now ship with standardized metadata, templates, and region look-up tables, simplifying downstream interpretation and reproducibility. 

New plotting features ensure that Nilearn remains up-to-date with the community's new requirements. The new transparent thresholding in statistical maps plots not only highlights statistically significant regions but also includes subthreshold locations, which provide key experimental context (Figure 2a). Additionally, Bland-Altman comparisons allow users to assess the level of agreement between two software packages about the magnitude of the statistical value observed at each voxel (Figure 2b). Further improvements in the plotting module ensured consistent default color map usage, correct treatment of sidedness in statistical maps, and improved surface visualization across backends.

Maintenance-focused development further reduced edge-case bugs, improved numerical consistency, and clarified deprecation paths. As a result, Nilearn estimators now behave more predictably within scikit-learn pipelines, and user-facing APIs better reflect invariant estimator properties.

Conclusion

Nilearn’s recent development cycle has advanced the library on several fronts – expanding plotting functionality while reinforcing stability and investing in durable maintainability. By fully integrating surface-based analyses across all modules and reinforcing alignment with scikit-learn standards, Nilearn now provides a stable and comprehensive framework for modern neuroimaging research.

Ongoing work will continue to incorporate new and better visualization methods, refine surface workflows, and improve interoperability with emerging neuroimaging standards. As the community grows, these efforts ensure that Nilearn remains a reliable, transparent, and extensible foundation for a holistic and reproducible brain imaging analysis.
