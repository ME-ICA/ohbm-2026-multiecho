Introduction

Neuroimaging has accumulated rich public ontologies, datasets, and software ecosystems, yet these resources remain difficult to use together in ways that support auditable inference. Cognitive ontologies such as the Cognitive Atlas1 standardize how we name constructs and relate them to tasks, but reproducible research additionally requires knowing which public data instantiate a construct, which derivatives constitute evidence, and which analytic operations produced those derivatives. Even as repositories increasingly follow FAIR (Findable, Accessible, Interoperable, Reusable) principles, the links from concept ↔ evidence ↔ method are often implicit and non-computable: concepts live in ontologies; datasets and statistical maps live in repositories (e.g., OpenNeuro, NeuroStore3, NeuroVault4, NeuroSynth5); and software knowledge is scattered across documentation and code. This fragmentation limits systematic comparison across studies and reliable grounding of automated analysis.

We introduce NeuroKG, a provenance-aware knowledge graph that makes these links between concepts, evidence, and methods explicit and computable, with the primary goal of supporting LLM- and agent-driven reasoning and retrieval over neuroimaging data. NeuroKG uses the OpenNeuro Vocabulary (ONVOC2) as a backbone for cognitive entities, aligns concepts to public empirical assets (datasets and map-level derivatives), and indexes a schema-defined library of analysis operations. By representing entities with stable identifiers and attaching explicit provenance to edges, NeuroKG supports both typed multi-hop queries and embedding-based similarity retrieval, enabling users and automated agents to move from a hypothesis to concrete public evidence and compatible analytic operations.

Methods

System goal and design rationale. NeuroKG is designed to make the links from concept - evidence - method explicit and computable, so that queries return auditable identifiers (datasets/maps/tools) rather than narrative recommendations. We therefore pair (i) a typed, provenance-aware graph that supports deterministic predicate-based multi-hop traversals (defined by explicit node/edge schemas, fixed relation semantics, and versioned graph snapshots) with (ii) embedding-based retrieval to handle long-tail cases (i.e., infrequent or weakly annotated tasks, contrasts, or datasets for which explicit labels or structured metadata are sparse or missing.). Figure 1 summarizes the schema/provenance model; Figure 2 summarizes query behavior and retrieval experiments.

Graph schema and provenance (Fig. 1). NeuroKG is implemented as a typed property graph (Neo4j) organized in three layers: ONVOC-aligned cognitive entities (concepts/tasks/contrasts), empirical assets (datasets/runs and derivative maps), and method assets (ToolSchema nodes). The knowledge base is constructed by ingesting cognitive entities from ONVOC (with cross-references to the Cognitive Atlas when available), empirical assets from OpenNeuro (BIDS datasets and run-level metadata) and NeuroVault (map-level derivatives; linked to NeuroSynth/NeuroStore records when available), and method assets from a schema-defined tool library (>2,000 operations wrapping FSL/SPM/Nilearn). Nodes and edges store provenance required for backtracking, including upstream identifiers (source, source_id), version/snapshot when available, ingest_time, evidence pointers (e.g., NeuroVault image IDs, dataset IDs, DOIs/citations, or execution records), and confidence plus mapping-rule identifiers for inferred links.

Typed multi-hop queries and evidence bundles (Fig. 2A–C). Natural-language query intents are compiled to type-constrained path templates that restrict traversal to semantically valid chains (e.g., Phenotype/Concept → Task/Contrast → Dataset → Run → DerivativeMap → ToolSchema; Fig. 2B). Queries return an evidence bundle (Fig. 2C): concrete dataset/map IDs plus compatible ToolSchema IDs, alongside provenance pointers. This makes retrieved evidence and recommended methods traceable, versionable, and directly actionable for downstream workflows.

Embeddings for long-tail retrieval (Fig. 2D). To support similarity search when task labels or metadata are incomplete, we learn text-augmented graph embeddings that combine (i) typed neighborhood structure (ontology context + cross-layer links) and (ii) available textual/structured metadata (dataset descriptions, task/contrast strings, derivative descriptors). Embeddings are exposed through a vector index for nearest-neighbor retrieval and visualized using UMAP over concept nodes (Fig. 2D).

Retrieval benchmark and analysis (Fig. 2E–H). We evaluated top-5 retrieval of ONVOC labels from dataset/query text: given a dataset description (and available task/contrast strings), retrieve the correct ONVOC concept/task among candidate ONVOC labels in scope. We compared a lexical baseline (TF–IDF) to a Gemini-based semantic retriever that ranks candidates by semantic similarity over the same text fields. To test generalization beyond near-duplicate descriptions, we used both a random split and a grouped split that holds out related items grouped by concept category. We report Recall@5 and Macro-F1, and stratify Recall@5 by label frequency (Head >100, Mid 10–100, Tail <10 examples; Fig. 2G–H).

Results

Scale and coverage. The current NeuroKG instance contains ~1.2M nodes and ~7M typed relationships, spanning ONVOC entities, 1,594 public datasets with associated derivative assets, and >2,000 versioned tool schemas.

Audit-ready cross-layer retrieval (Fig. 1; Fig. 2A–C). NeuroKG supports deterministic traversals that connect a high-level query to concrete public evidence and compatible analysis operations. Example queries (Fig. 2A) are resolved into typed path templates (Fig. 2B) and return an evidence bundle (Fig. 2C): OpenNeuro dataset IDs (and run/map identifiers when present) together with compatible ToolSchema IDs. Because outputs are identifiers and schema objects with provenance pointers (Fig. 1), results are inspectable and directly usable for downstream workflows and agent grounding.

Semantic structure in learned representations (Fig. 2D). Embeddings learned over the typed graph recover coherent organization of ONVOC concepts: the UMAP shows separation and local clustering by ConceptClass (e.g., attention, executive function/cognitive control, language, perception, social function), indicating that the representation captures higher-level semantic structure while preserving local neighborhood relations needed for retrieval.

Overall retrieval performance (Fig. 2E–F). On the top-5 retrieval benchmark, the Gemini-based semantic retriever outperformed TF–IDF across both evaluation regimes. Under a random split, performance increased from 0.66→0.85 in Recall@5 and 0.46→0.70 in Macro-F1. Under the stricter grouped split, performance decreased for both methods but semantic retrieval retained an advantage (Recall@5: 0.25→0.40; Macro-F1: 0.15→0.35), consistent with improved generalization beyond lexical overlap.

Head/mid/tail behavior (Fig. 2G–H). Stratification by label frequency showed that gains are concentrated in the mid and tail of the distribution. In the random split, head concepts were near the ceiling for both methods, while mid improved (~0.50→0.75) and tail improved (~0.40→0.60). In the grouped split, overall performance dropped, but improvements persisted for head (~0.32→0.45) and mid (~0.20→0.35). Tail performance was low under grouped evaluation, reflecting both scarcity and heterogeneity in long-tail descriptions.

These results indicate that NeuroKG enables audit-ready multi-hop retrieval (IDs + provenance) while improving concept search beyond lexical matching, with the largest gains in mid/tail concepts under stricter grouped evaluation.

Conclusion

NeuroKG operationalizes a simple premise: reproducible neuroimaging requires computable links from concepts to the public evidence that instantiates them and the methods that transform that evidence. By representing ONVOC-aligned cognitive entities, OpenNeuro/NeuroVault empirical assets, and versioned tool schemas within a typed graph, and attaching explicit provenance to nodes and edges, NeuroKG enables audit-ready retrieval that supports both multi-hop reasoning and similarity-based discovery.The main bottleneck remains incomplete or inconsistent upstream metadata and missing provenance for derivatives, which limits link specificity for long-tail assets. Ongoing work expands crosswalk coverage across phenotype axes, strengthens linkage to execution records where available, and formalizes large-scale evaluation of mapping accuracy and retrieval quality. More broadly, NeuroKG provides a substrate for trustworthy automation by requiring AI systems to operate over explicit, versioned concept–evidence–method links rather than free-text narratives.
