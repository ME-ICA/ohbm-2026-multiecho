Introduction

For multicenter research consortia with existing or ongoing data collection, a key challenge is determining which clinical or cognitive assessments are available at each site, and for which subjects. Site-specific naming, organization, and access control complicate the curation of measures for pooled analyses, highlighting the need for standardization tools for assessment data.1 Neurobagel is a global tool ecosystem for decentralized cohort discovery that aims to address these challenges. Using Neurobagel, sites can easily build data dictionaries for local tabular data using standardized, FAIR vocabularies and create harmonized representations of subject data in a discoverable local Neurobagel “node.”2

Yet, the diversity of assessments used across different consortia makes finding one vocabulary capturing all domain-specific concepts challenging. One solution is to combine multiple vocabularies, but this requires expert guidance to create crosswalks for overlapping terms and ensure consistent term use. A single mega-ontology with every term of interest across consortia is also unrealistic, given the high governance burden and complexity of defining assessments universally. For consortia, an effective solution for within-consortium assessment term harmonization must build on existing coordination and governance.

Community-governed vocabularies offer the flexibility to describe decentralized data using consistent terminology tailored to the community’s needs. The Brain Imaging Data Structure has shown how subcommunity-driven development is crucial for adapting a standard to different research contexts, while also improving neuroimaging data reusability.3 Applying these principles, we extended Neurobagel to allow consortia to implement standardized vocabularies for assessments of interest without deep technical expertise. We co-developed this functionality with the ENIGMA-Parkinson’s Disease (PD) consortium,4 who are early adopters as the first Neurobagel subcommunity.

Methods

We developed a process for curating a community vocabulary of assessments used across sites in a consortium (Fig. 1). To use familiar, accessible formats, we designed a Google Sheet template for curating the terms. The template captures essential term metadata such as name and description, and assigns a unique identifier to each term. Sites or a coordinating team can directly build an initial term list, while an optional “status” field is provided to support both ad-hoc updates and consortium-defined term inclusion criteria. We also developed documentation for using the template, with guidelines for each field.

Next, we created a workflow to simplify the process of transforming a raw terms list into a machine-readable vocabulary following linked data principles, such as ensuring identifier uniqueness and adding a unique namespace for terms. We developed an automated GitHub actions workflow that validates and converts a known community Google Sheet into a JSON file following a standardized vocabulary format, and then stores it in a central, publicly accessible repository (https://github.com/neurobagel/communities). Since we onboard groups that participate in this workflow, our process also ensures that only community-governed vocabularies are made available for raw data annotation and harmonization with Neurobagel tools.

Finally, we introduced configurability for Neurobagel tools to support the new subcommunity vocabularies. In the Neurobagel annotation tool, users can now select a custom vocabulary to use for annotating their tabular data (https://beta-annotate.neurobagel.org). These vocabularies are pulled automatically from the central community vocabulary repository, allowing consortia to easily stay up to date when creating or updating data dictionaries. The Neurobagel CLI and node API, which create and expose harmonized representations of subject data for discovery,5 can now also be configured at runtime to use a specific community vocabulary for dataset validation.

Results

Using our documented template for a community-specific assessments vocabulary, ENIGMA-PD was able to curate over 130 well-defined terms reflecting clinical or cognitive measures relevant for ENIGMA-PD research studies, with minimal effort. Assessment names and descriptions from local datasets were added by sites asynchronously to a central Google Sheet. Through our automated GitHub workflow, these curated terms are now publicly available as a community standardized vocabulary in Neurobagel (https://github.com/neurobagel/communities/blob/main/configs/ENIGMA-PD/assessment.json), and can be used consortium-wide to annotate local data. Within the vocabulary, the consortium established distinct terms for different assessment versions, related assessments for different clinical subgroups, and assessments completed under different medication conditions, reflecting the granularity needed for meaningful data capture. Because Neurobagel’s current standardized data model focuses on assessments and demographics as core phenotypic variables for cross-dataset cohort discovery,5 sites also included non-assessment terms in the assessments vocabulary as a workaround to capture additional subject information. For internal coordination, the consortium also added a custom metadata field for assessment “domains” (e.g., “Sleep”, “Language”) to the curation spreadsheet.

Four ENIGMA-PD sites (Groningen, Nijmegen, Montreal, Amsterdam) thus far have further successfully annotated and generated harmonized data for local datasets using the consortium assessment vocabulary in existing Neurobagel tools.5 Without changing sites’ locally stored data and naming practices, this harmonization has enabled search of subject-level availability of 21 consortium-defined assessments across 386 subjects (December 2025) using the ENIGMA-PD Neurobagel node (https://enigma.neurobagel.org).

Conclusion

We have expanded the capabilities of Neurobagel to support within-consortium data harmonization and discovery, introducing a framework for a community to curate assessment terms used across sites and annotate local data using the resulting vocabulary. These community-defined vocabularies allow consortia to harmonize assessment metadata without sacrificing detail, simplifying cross-site comparisons, while remaining maintainable due to their well-defined scope. Our approach also simplifies adoption of best practices for creating standardized terminology, such as machine readable identifiers, unambiguous definitions, and clear governance for vocabulary management. As a proof-of-concept of our framework, the ENIGMA-PD implementation shows both the utility of a flexible vocabulary curation model for harmonizing terms used in a consortium setting, and the need for standardized terminology for other variables beyond assessments. Future expansion to other consortia, along with expanded configurability of standardized variables within the Neurobagel data model, will allow richer phenotypic detail to be harmonized and queried across sites. Our open repository for community-defined vocabularies lays the groundwork for cross-consortia integration and vocabulary crosswalks informed by term usage, in turn facilitating connections across global multi-site data.
