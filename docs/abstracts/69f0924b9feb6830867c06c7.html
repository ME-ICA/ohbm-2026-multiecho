Introduction

Deep learning now plays a central role in the processing and analysis of neuroimaging data. However, neuroimaging presents several specific characteristics that limit the direct use of standard deep learning frameworks. These data are three-dimensional, include physical information such as voxel spacing, may be longitudinal, and usually require dedicated preprocessing steps such as intensity inhomogeneity correction, denoising, motion correction, spatial normalization or intensity rescaling. To facilitate working with neuroimaging data, specifications such as the Brain Imaging Data Structure1 (BIDS) have been proposed, along with neuroimaging-specific preprocessing tools like BIDS Apps or Clinica2. Concurrently, general-purpose deep learning frameworks for medical imaging, such as MONAI3, have been developed, but they lack integration with neuroimaging-specific data standards and preprocessing pipelines.

ClinicaDL is a deep learning framework specifically designed for neuroimaging that natively integrates with BIDS data organization and neuroimaging preprocessing pipelines.4 It enables the training and evaluation of neural networks on data organized according to BIDS or its derivatives, and produces standardized outputs that include training logs, evaluation results, and all the information required to ensure experiment reproducibility. The framework also provides utilities for handling patches and 2D slices extracted from 3D volumes, generating synthetic data, and unbiased splitting of longitudinal data.

While the initial version of ClinicaDL relied on a command-line interface that ensured accessibility but limited flexibility and interoperability with other Python medical imaging libraries, the latest version has transformed ClinicaDL into a full Python API. This transition allows for more customizable workflows and seamless integration with the PyTorch ecosystem.

Methods

ClinicaDL takes as input neuroimaging data organized according to the BIDS standard, or derivatives such as the outputs of Clinica, and provides tools to manipulate this structure, such as efficient image loading, extraction of patches or slices, and longitudinally aware splitting into training and test sets. ClinicaDL also provides tools for generating synthetic images organized in a BIDS-compliant dataset.

Because no standard exists for neural network training outputs, ClinicaDL defines its own structure, called the Model Analysis and Processing Structure (MAPS) (Fig. 1). The MAPS structure stores the training outputs (e.g., checkpoints and logs) as well as the evaluation results. It also contains all the elements required to reproduce the experiment, such as user-defined variables and the Python environment used. The advantages of such a standardized output are threefold: (i) it provides a clear and consistent way to store and track experimental results, (ii) it facilitates experiment reproducibility, and (iii) it enables fair comparison between deep learning models by ensuring that they are trained and evaluated under comparable conditions.

ClinicaDL supports image classification, regression, reconstruction, and segmentation tasks, all handled by a common trainer that, by default, abstracts away the complexity of the training process while still allowing users to easily override the default implementation to customize their experiments. This trainer can resume interrupted training and offers high-performance computing features, including automatic mixed precision and data- and model-parallelism.

Regarding its implementation, ClinicaDL relies on the PyTorch framework and leverages several tools from its medical imaging ecosystem, such as MONAI and TorchIO5. The key distinguishing features compared with the MONAI framework are ClinicaDL’s native support for reading BIDS-organized datasets and its standardized output format.

Results

ClinicaDL is an open-source project, with its code hosted on GitHub (https://github.com/aramis-lab/clinicadl), the Python package available on PyPI, and the new Python API fully documented, including tutorials to help users get started (https://clinicadl.readthedocs.io/en/stable/). The project follows standard software development practices, including continuous integration with unit and functional tests (98% coverage) and compliance with semantic versioning. One developer works on the project full-time, and external contributions have so far been limited; however, we hope the new, more contributor-friendly version will help to build a community.

The main change introduced in version 2 is the transition from a command-line interface to a class-based Python API (Fig. 2). ClinicaDL now offers a collection of ready-to-use classes (e.g., common loss functions, metrics, and transforms) that enable users to run deep learning workflows with minimal effort, while still allowing them to define custom classes to tailor their own pipelines. In addition, the default training and evaluation logic can be easily overridden, giving advanced users full control over their workflows.

Alongside the increased flexibility for users, the new design also improves modularity for developers. ClinicaDL is now easier to maintain and extend, as contributing typically involves adding a new class to the existing collection. 

Conclusion

ClinicaDL offers an accessible entry point for deep learning in neuroimaging, requiring only that the data be organized in a BIDS-like structure. With its standardized outputs, ClinicaDL emphasizes experiment management and reproducibility, making it particularly well suited, for example, for benchmarking. In addition, the new Python API provides increased flexibility and interoperability within the PyTorch medical imaging ecosystem, enabling advanced users to design complex pipelines. We hope that this more developer-friendly version will foster an active community in deep learning for neuroimaging that will enrich the project with new and innovative workflows.
