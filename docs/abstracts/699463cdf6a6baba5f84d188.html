Introduction

A major goal in the field of computational psychiatry is to develop reliable biomarkers for psychiatric illness. Traditional case-control approaches largely fail to provide meaningful insight into psychiatric disorders because the implied assumption that clinical groups are distinct and homogeneous do not match the continuous and heterogeneous nature of the biology.

Normative Modelling (NM) has emerged as a promising statistical method for understanding heterogeneity in clinical cohorts1. This paradigm moves away from traditional case-control approaches by estimating trajectories of healthy development - anatomical, neurological, behavioral - from a large reference dataset, and mapping individual observations to deviations from these trajectories. Transforming observations to deviation scores involves regressing out clinical covariates - age, sex, total brain volume - rendering the deviation space mostly independent from these variables. The deviation features thus form a robust basis for subsequent analysis at the level of the individual.

PCNtoolkit is an open-source python package for NM, which was developed to fulfill two critical needs. First, to provide a user-friendly software package including multiple algorithms specifically tailored to neuroimaging data, and second, to ease reproducibility. The present work introduces PCNtoolkit version 1.x.x, which has been re-written from the ground up following best practice software development principles, providing an enhanced interface to familiar NM techniques, refinement of underlying statistical algorithms, new features and more robust implementational standards.

Here, we present an overview of the main workflow of  PCNtoolkit and highlight new features including longitudinal NM, HBR model comparison, data synthesis, data harmonization, post-hoc-analysis, and federated learning methods; transferring, extending, and merging models. Methods

Whilst the original version of PCNtoolkit (version 0.x.x) has been used in many clinical applications,2 a long series of incremental modifications and extensions made a code refactor necessary in order to improve code robustness and extensibility. To address this, PCNtoolkit 1.x.x is a completely rewritten version of the software that is built from the ground up using object-oriented software design principles. PCNtoolkit 1.x.x supports the most important estimation algorithms used in prior versions including Bayesian linear regression (BLR),3 and hierarchical Bayesian regression (HBR)4 as well as introducing many new features. These include: 

  • Improved model visualisation and diagnostic tools

  • A new model runner class to support cluster computing

  • Better support for federated learning,4 allowing decentralised extension and merging of large scale models by passing parameters between study centres

  • New beta likelihood function for HBR4 allowing inference for interval data

  • Approaches for longitudinal inference, on the basis of velocity models and thrive lines

  • Site harmonisation approaches on the basis of normative models

  • Human readable model format (using JSON format)

  • Completely revised documentation and tutorials

In the foregoing sections we provide several illustrative applications to showcase the functionality of the software.

In the first set of analyses, we employed a Hierarchical Bayesian Regression (HBR) model with a SHASHb likelihood, which allows modelling of positive and negative skew in addition to platy- and leptokurtic distributions in a single family (Fig 1A). This distribution has four parameters, mu, sigma, epsilon, and delta, and PCNtoolkit supports a flexible model specification including linear and nonlinear expansions of each, plus random effects, which are useful to accommodate site effects (Fig 1B). Here, mu and sigma are both taken to follow a linear regression on age through a 5-knot, degree 3 b-spline basis expansion. In addition, the intercept of mu has been set to contain additive random effects of sex and scan site. To ensure sigma is positive, it has been mapped to the positive domain with a softplus function. The remaining parameters, epsilon and delta, are taken to be single scalar values without linear or random effects. Delta has also been mapped to the positive domain through a softplus mapping, and a constant value of 0.6 has been added to the mapped value to ensure numerical stability (see 4  for details)..

For the first set of analyses, we use the publicly available FCON1000 dataset (Fig 1C) which consists of MRI scans of 1078 subjects collected at 33 sites. From these scans, parcellations derived from the Destrieux atlas and subcortical volumes were extracted using the freesurfer software. Analyses were performed on two selected features;Left-Lateral-Ventricle and rh_G_cuneus_thickness,

For the second set of analyses, we fit an HBR model with a beta likelihood to model fractional anisotropy measures from the fornix derived from UK Biobank using the TBSS processing pipeline. This is a challenging imaging derived phenotype to model because fractional anisotropy is constrained to the unit interval, and therefore continuous likelihood functions are not appropriate.

For all models, we performed a full posterior estimation using NUTS sampler with 4 chains of 3000 samples, of which the first 1000 were discarded. For all 582 parameters of 6 models, the 'Rhat' statistic indicated strong convergence (mean 1.0007, std 0.003) (Fig 1D).

Results

We perform several analyses to illustrate the additional features of PCNtoolkit v1.x.x.

First, we show a good fit of the SHASH-b1 model to non-Gaussian data derived from the FCON1000 dataset for the left lateral ventricle (Fig 2A). This example also highlights several of the new plotting capabilities of PCNtoolkit, including the ability to overlay different batch effects on the population level centiles (shown in the left panel using different colours and marker shapes), and the ability to show conditional densities for a given value of one of the covariates (vertical blue distribution). In the right panel we show quantile-quantile plots which can be used to assess the fit of the model in terms of the distributional shape. 

Next, we show the capability to harmonise data to a common set of centiles (Fig 2B). Normally, PCNtoolkit estimates an independent set of centiles for each level of the batch effect, using Bayesian partial pooling of parameters to share information between these. However, PCNtoolkit provides the ability to align data from different models to a common reference model and derive the data points that would have been obtained had the data been acquired on a different scanner. Note that this is fundamentally different from data harmonisation using techniques such as combat because it aligns data to a common reference model (that might be derived from completely different data) via an invertible transform that means that new data can seamlessly be integrated and that data can be harmonised to a different scanner without needing to refit the model. 

Another important feature of PCNtoolkit is the ability to perform analyses in a federated learning framework. We show an illustrative example in Fig 2C, where we exclude two sites from the FCON1000 sample, then fit either a naive model (that is, one that only includes these two sites) or two variants of federated learning models. First, we perform a ‘model transfer’, which employs the population level model (fit to all remaining sites) as an informative prior to improve the predictions on the left out sites. Next, we perform a ‘model extension’ which updates the population level model to also include the new data. As shown by the median predictions depicted in Fig 2C, both federated models perform similarly and considerably better than the naive model, which results in a biologically implausible trajectory, due to insufficient data. 

Finally, we show an example of the new beta likelihood function fit to fractional anisotropy data derived from the UK Biobank study. This shows a good fit that respects the interval nature of the data, in that all predictions are constrained to lie within the unit interval (Fig 2D).  

Conclusion

Here, we have introduced PCNtoolkit 1.x.x, which is a completely revised and rewritten version of the software to promote usability, maintainability and scientific reproducibility. We have also shown example applications to highlight some of the new functionality, including improved model visualisation tools, normative model-based data harmonisation, improved functionality for different variants of federated learning and a new data likelihood for interval data. 

PCNtoolkit v1.x.x supersedes earlier versions in terms of nearly all functionality and support for earlier versions will gradually be phased out. The only models that were not reimplemented in the new version are Gaussian process models, which –although flexible– have limited scaling capability to large scale datasets. Importantly, in view of the comprehensive redesign and suite of new functionality, models estimated with PCNtoolkit v.1.x.x are not compatible with earlier versions (and vice versa). We are working on updating all publicly available lifespan normative models for cortical thickness, brain volume, fractional anisotropy and functional connectivity2,3 and these will be released in coming months.  

We consider that the ability to estimate normative models in a decentralised fashion using federated learning is essential in view of the shift of many datasets (such as UK Biobank) toward requiring that data analytics be performed on secure, proprietary platforms. As we have shown, this functionality enables such models to be estimated without ever needing to share data.

Further methodological functionality will continue to be added to PCNtoolkit as it is developed, and in the spirit of open science, we welcome contributions from the community.
