Introduction

Neuroimaging studies have shifted from localized region activation to connectome-based approaches to understand the neural underpinning of cognitive processing1. This focus on interactions across brain regions has promoted the use of graph theory-based methods. By treating the brain as a network, graph theory allows for the quantification of higher-order features – such as global efficiency and small-worldness – that characterize the topological organization of the brain. These features are often used to explain individual differences across various phenotypes. However, strong evidence suggests that variations in data preprocessing and analysis within graph theory lead to fundamental variability in research findings, a major concern in the context of the replication challenge2. One solution to this challenge is the implementation of systematic robustness checks using multiverse analyses to test findings across plausible analysis paths2. However, implementing such approaches requires knowledge of the plausible decisions available, also called as a knowledge space, in data preprocessing and analysis.

In a previous study3, we systematically extracted the preprocessing and analysis pipelines of 220 functional Magnetic Resonance Imaging (fMRI) graph analysis studies. We identified 61 distinct steps, 17 of which involved debatable parameter choices. We also created an interactive web-based application, METEOR, which allows to explore the knowledge space of these pipelines (link). METEOR provides high educational value and facilitates access to knowledge for designing well-informed robustness (multiverse) analyses. To ensure the app's sustainability, we aim to automatically update its knowledge space using a Large Language Model (LLM)-assisted framework. Here, we present this framework and findings from this initiative.

Methods

The LLM-assisted framework, illustrated in (Figure 1), comprises two primary components: (i) the creation of a benchmark dataset and (ii) fine-tuning an LLM for information extraction from the relevant literature. This study presents the dataset development phase and outlines the fine-tuning implementation as future work. The workflow for creating the dataset is as follows:

1. Corpus collection

The fMRI studies were collected from PubMed, Scopus, and Web of Science3. All collected documents were stored in a directory, forming the raw corpus for subsequent processing.

2. PDF-to-JSON conversion

All PDFs were converted to structured JSON using a standardized parsing script. The resulting JSON files contained the extracted text and metadata, with automatic removal of headers, footers, and repeated section labels.

3. Prompt engineering and LLM-based pre-annotation

Each full-text JSON was processed with a prompt applied to GPT-5. The prompt implemented: (i) schema definition, (ii) paragraph-selective extraction of methodological content, (iii) mapping of preprocessing steps to a standardized schema with generation of an annotated JSON file, and (iv) creation of a missing-label summary for quality control. The prompt was refined iteratively to improve extraction quality across metadata families and preprocessing steps.

3.1 Schema definition

A schema defining 61 steps spanning structural, functional, noise-removal, and graph-analysis families was specified within the prompt, along with methodological metadata³. For each step, four sublabels were defined: Step Number, Algorithm, Software, and Parameter. Detailed definitions of all steps and annotation requirements were included in the prompt.

3.2 Paragraph-selective extraction and global step numbering

Paragraph selection was implemented within the prompt, where GPT-5 received the full article text and focused on paragraphs containing methodological information based on the schema. When overlapping information occurred across sections, the model prioritized content in the order: Methods → Results → Discussion → Abstract/Introduction. Step numbering followed a single global sequence inferred from linguistic cues and common neuroimaging workflows4.

3.3 Annotated JSON file

The prompt produces an annotated JSON file in which the LLM maps metadata and preprocessing steps to the predefined schema. Relevant text spans are detected and assigned appropriate labels, resulting in a structured, machine-readable output that can be directly imported into HumanSignal and compared with manually extracted annotations from the previous study2.

3.4 Missing-label summary

For each paper, the prompt also generated a missing-label summary listing metadata families and preprocessing steps that were absent, incomplete, or ambiguously reported. This file supported automated checks and guided later human review.

4. Automated quality control

After importing the annotated JSON files into HumanSignal, a Python script was applied to the LLM-generated annotations. The script matched extracted steps to manually identified steps from the previous study3, detected missing or duplicated steps, checked step-number sequences, harmonized parameter formats, and verified span offsets. All discrepancies were compiled into structured Quality Control (QC) reports.

5. Final human review and benchmark dataset assembly

In the final round, annotated JSON files were imported into HumanSignal for expert review. Guided by QC reports, annotators completed missing or ambiguous fields, corrected step assignments, software labels, and parameters, refined supporting spans, and verified global step-number consistency. After this targeted human-in-the-loop correction, a final inspection of preprocessing and graph-analysis pipelines was performed. The validated annotations were exported as JSON, CSV, and Excel files, forming the benchmark dataset for subsequent LLM fine-tuning to extract analytical decisions from graph-based fMRI studies.

Results

From the initial literature corpus, an annotated subset of 220 human fMRI studies was completed to generate the benchmark dataset (see Figure 2).

The initial benchmarking phase revealed considerable variation in the reporting quality of preprocessing steps in the analyzed literature. Main preprocessing steps, such as motion correction, spatial normalization, and smoothing, were generally described with clarity. In contrast, graph analysis-related information (e.g., atlas/parcellation, connectivity metrics, edge definitions, thresholding rules, graph-construction parameters) was often sparse, inconsistently defined, or reported only implicitly.

Initial prompt limitations

We developed an initial prompt that performed satisfactorily; however, after extracting data from the first 100 of 220 papers, we observed substantial inconsistencies, particularly for graph-analysis steps. The Initial Prompt yielded the highest proportion of missing fields, including 934 missing-information cases overall, comprising 607 graph-analysis-related omissions, 9 omissions in other preprocessing steps, and 318 metadata gaps, indicating insufficient domain specificity for graph-analysis extraction.

To address this limitation, we adopted a targeted refinement strategy. For the first 100 papers, we applied a dedicated graph-analysis prompt with detailed definitions and examples, then merged its specialized JSON output with preprocessing annotations using a custom Python script. For the remaining 120 papers, a fully updated unified prompt was applied, enabling complete extraction in a single pass. This staged approach markedly improved the consistency, completeness, and reliability of graph-analysis annotations across the dataset.

Development of an updated prompt

To address accuracy limitations of the initial prompt, we designed a specialized graph-analysis-only prompt with detailed definitions of all graph analysis steps (atlas specification, ROI extraction, connectivity computation, graph construction, metrics, aggregation), explicit software examples (e.g., BCT, Nilearn, GRETNA, NetworkX), algorithm-level distinctions (e.g., weighted vs. binary graphs, proportional thresholds, modularity detection), and representative parameter examples (e.g., density thresholds, Fisher z-transformation, community-detection settings).

Improvements by the integration of the new prompt

For the first 100 papers, we merged the initial-prompt and graph-analysis-only JSON files using a Python script, producing a single combined file per paper containing both preprocessing and graph-analysis information. The script also identified remaining gaps and inconsistencies, revealing 38 issues, 12 related to preprocessing steps and 26 to metadata, which were subsequently corrected by human reviewers in HumanSignal.

For the remaining 120 papers, we applied the fully updated prompt with integrated graph-analysis definitions, enabling joint extraction of preprocessing and graph-analysis steps in a single pass. This resulted in substantially fewer omissions, with only 36 graph-analysis and 55 metadata gaps remaining, all of which were resolved during final human validation prior to benchmark release.

Final human validation and benchmark release

All remaining discrepancies identified at any stage were corrected by expert human annotators during the final validation round. The fully verified annotations were then exported in JSON, CSV, and Excel formats, forming a high-quality benchmark dataset for future LLM fine-tuning on automated extraction of methodological decisions in graph-based fMRI studies.

Conclusion

This work demonstrates a scalable and systematic framework for constructing a high-quality benchmark dataset to support LLM-assisted extraction of fMRI preprocessing and graph-analysis-based fMRI methodological decisions. Our findings reveal clear gaps in methodological reporting, particularly for graph-analysis steps, where definitions were often implicit, underspecified, or entirely absent. The development of a specialized graph analysis prompt, combined with a dual-pass extraction strategy and targeted reviewer validation, substantially improved annotation completeness and accuracy, reducing missing-information cases and resolving graph analysis-relate omissions identified in the initial prompt.

By integrating explicit definitions, algorithm-specific examples, and software-level guidance into the graph analysis-related prompt, we were able to recover methodological details that were previously inaccessible by using the first version of a more general prompt. The Python-based merging pipeline and subsequent reviewer inspection further ensured that implicit, ambiguously stated, or inconsistently formatted information could be identified and incorporated into the final dataset.

The resulting benchmark dataset, covering both preprocessing and graph analysis-related methods with detailed, reviewer-verified annotations provides a robust foundation for fine-tuning domain-specialized LLMs, such as open-source BrainGPT5, that will be performed in the future study. These models will be able to autonomously parse, structure, and update methodological information in neuroimaging literature. This capability is essential for enabling automated integration of new studies into the knowledge space and for improving transparency and the design of large-scale multiverse analysis within the future fMRI literature. Future work will leverage this benchmark to train and evaluate LLMs and expand the framework to additional neuroimaging modalities and analytical domains.
