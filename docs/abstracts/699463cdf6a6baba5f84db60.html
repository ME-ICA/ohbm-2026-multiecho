Introduction

Neuroimaging pipelines for the analysis of task functional Magnetic Resonance Imaging (task-fMRI) data are composed of multiple steps covering data preprocessing and statistical analysis. Each pipeline step requires researchers to make multiple decisions in order to set the available parameters. In their large-scale study, Botvinik-Nezer et al. [1] invited researchers to analyze a shared dataset to answer a set of pre-defined research research questions. As a result of this experiment, each team constructed a different pipeline and sometimes reported contradictory results. The flexibility of researchers while deciding on parameters is also referred to as the researcher degree of freedom and the induced differences in the results as analytical variability.

To examine potential sources of analytical variability resulting from the researcher degrees of freedom, Carp [2] identified the parameter values used in the literature, compared the resulting pipelines and demonstrated pipeline variations. In neuroimaging research, throughout the years there have been multiple endeavors to encourage code sharing alongside research papers [3,4]. Increasing code sharing effectively creates new opportunities to better understand pipelines by directly examining the source code accompanying scientific papers.

The aim of this work is to shed light on the sources of analytical variability. We assess the researcher degrees of freedom by collecting and analyzing a codebase of open source pipelines in AFNI, FSL, and SPM. 

Methods

Using Github code search API, we created a codebase from openly available scripts of neuroimaging pipelines comprising 3000 code files dated from 2010 to 2025 and sampled from 93, 157, 312 unique repositories for AFNI, FSL, and SPM respectively.

The process of codebase creation is including query design and retrieval of the code scripts (see Fig. 1.A). For each pipeline in the codebase, we extracted all parameters along with their values (see Fig. 1.B). For example, the full width at half maximum of the spatial smoothing kernel in afni_proc.py is given after the flag -blur_size. In design.fsf in FSL, it is defined after set fmri(smooth). In SPM the smoothing kernel is defined with the command spm.spatial.smooth.fwhm.Each unique repository in the codebase corresponds to one software pipeline. For the identification of preprocessing pipelines, we set motion correction step as the baseline.

The query table (see Fig. 1 C) summarizes the query rules to match AFNI, FSL, and SPM pipeline scripts from GitHub. We implemented queries with GitHub REST API (v3) and PyGitHub (version 2.7.0). Since the GitHub search functionality is limited to returning 1000 code files per query, we performed a separate query per software to maximize the number of results returned. The queries were run on June 03, 2025. We excluded AFNI, FSL, and SPM source codes, as well as animal pipelines (exclusion of repositories containing animal names such as rat, mice, monkey, pig, sheep and marmoset in the folder names or names of the repositories).

Results

Use of preprocessing steps in each pipeline 

The use (or not) of each preprocessing step is summarized in Fig. 2a. In FSL, nearly all preprocessing steps are always implemented, except for the slice timing correction (present in 19% of the repositories) and segmentation (96%). For SPM pipeline scripts, the least implemented step is slice timing correction (67%), followed by normalization (80%) while coregistration and segmentation are the most used steps (both 93%).  In AFNI pipelines there are more variations, the least performed step is slice timing (34%) and the most performed step is the coregistration (87%).

Asessment of Parameter Preferences

Fig. 2b displays the count of parameters for which a given percentage of pipelines use the default value (as fixed by the software package). For instance, the uppermost orange diamond Fig.2b indicates that for 14 of the normalisation parameters in SPM, the default value is used in over 95% of the pipelines.

We found that despite predominantly choosing the software-provided default values, there are variations in parameter choices for each software in all the different steps. For each software packages (AFNI, FSL and SPM) the most varying parameters are listed in Fig 2c. 

For motion correction, SPM pipelines have a total of 18 parameters, among those only two are varying (i.e. use a non default value more than 15% of the time) Fig 2c. For coregistration, AFNI pipelines have 4 parameters to be set by the researchers, FSL have 6 and SPM 14. Among those, AFNI and FSL have one varying parameter each while SPM pipelines mainly use default values. For normalization, AFNI pipelines have 8 parameters, FSL pipelines have 5 and SPM 18. AFNI pipelines show the most variation in this step with 6 varying parameters while FSL and SPM have respectively 1 and 2 (see Fig 2c). For segmentation, among the 12 available parameters in SPM, one varying was identified. In FSL pipelines, set fmri(bet_yn) is the parameter indicates segmetation step availability in the pipeline. In AFNI pipelines, preprocessing does not involve segmentation step [5]. For smoothing, the single parameter (smoothing kernel) is varying for all software packages. 

Conclusion

We explored pipeline variations for preprocessing step chosen by researchers in 3 neuroimaging software packages. In the codebase, we observed varying parameter choices for each step of preprocessing. In general SPM pipelines more often use the software defaults. The pipelines with the greater number of  varying pipelines belong to AFNI.

As a summary of our analysis, among the total of 109 parameter available across all software, we identified a subset of 17 parameters that vary. Future investigation of analytical variability could focus on targeting those parameters.

In preprocessing step of task-fMRI analysis, researcher preferences seems to be influenced by software default values. The value of the smoothing kernel is the most varying parameter of the pipelines. We note that another parameter (i.e. "written voxel sizes") may be interacting with smoothing kernel values. Testing interactions of parameters and smoothing kernel preferences require the access of the relevant data of the scripts since these parameter choices may have been influenced from acquisition resolution.

This work on pipelines collected from GitHub allows to identify several differences in available parameters and their associated values. Further work will include a larger collection of source scripts for a more exhaustive analysis.  Still, we hope this preliminary results can already be useful for beginners in task fMRI, software developers and for reproducible science as well as to guide future investigations into analytical variability.
