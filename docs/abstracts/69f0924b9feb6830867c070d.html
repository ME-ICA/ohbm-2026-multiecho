Introduction

The frequency-following response (FFR) is a robust electrophysiological signal that encodes an incoming auditory stimulus in the auditory system with high temporal and spectral fidelity.^1 The FFR is generated by nuclei along the early auditory pathway, from the brainstem through primary auditory cortex. Because it sheds light on subcortical auditory processing and can be acquired simply and at low cost with scalp-recorded electroencephalography (EEG), the FFR has contributed greatly to our understanding of human subcortical auditory processing and has been used to identify altered auditory processing in clinical populations.

Despite the prevalence of the FFR in auditory neuroscience, there are no standardized tools for processing and analyzing FFRs. While resources have been made available by individual researchers, they are often built on non-standard data formatting and analysis code, frequently relying on closed-source software. Building on the strengths of the human brain mapping community, we therefore sought to establish a robust, reproducible, open processing pipeline for the FFR, which we are calling FFRPREP.

Methods

We developed the FFRPREP architecture as a BIDS App .^2 Critically, we assume data are compliant with the brain imaging data structure (BIDS) for EEG data,^3 which enables standardization of downstream processing and analysis methods. FFRPREP heavily uses MNE-Python^4 across the pipeline. The pipeline itself is constructed using Nipype,^5 which allows for extensibility, parallelization, and efficient pipeline management.

FFRPREP is structured with separate modules for preprocessing, analysis, and reporting. 

In preprocessing, data from a single participant, session, and run are loaded into an MNE `Raw` object using MNE-BIDS. Channels are then re-referenced according to a user-visible flag, with the default being average channel referencing. Data are then filtered using MNE’s filter_data method and subsequentely epoched based on the event times and descriptions provided in the BIDS events.tsv file accompanying the EEG data. Finally, it generates an averaged response for each event type as an MNE `Evoked` object.

In analysis, we have implemented a power computation and a signal-to-baseline root mean squared calculation, each of which have been used analytically and can also provide insights into data quality. To characterize a key unique aspect of the FFR, we calculate the pitch-tracking fidelity of the FFR using autocorrelation. We also calculate confidence values for each pitch estimate. Since the FFR is expected to encode the fundamental frequency (or pitch) of an auditory stimulus up to approximately 500 Hz, this metric is commonly used to quantify the integrity of early auditory processing across task conditions and participant populations.

Upon completion, FFRPREP generates interactive HTML reports that include pipeline details, data summaries and informative figures to support data transparency, provenance, quality control and reproducibility in a standardized manner. As a BIDS-App, FFRPREP constructs and adapts the underlying workflows based on user-defined input parameters set through a command-line interface available in version-controlled software containers. This provides a lightweight, self-contained software environment for reproducible and standardized preprocessing and analysis.

Containerization and documentation updates are automated through GitHub Actions, allowing streamlined updating of all resources once changes have been introduced to the main FFRPREP code repository.

Following software development best practice, we require unit testing for each contribution to the FFRPREP package. Contributors can take advantage of functions provided in the `datasets` module for pulling raw and preprocessed EEG data from our OSF repository.

Results

We successfully developed and deployed FFRPREP as a fully functional BIDS App for standardized FFR preprocessing and analysis. The pipeline has been tested on example FFR datasets and demonstrates expected functionality across all implemented modules.

FFRPREP successfully processes FFR data from BIDS-formatted EEG datasets, with complete runs typically completing in minutes per participant depending on the number of trials, analysis parameters selected and computing architecture. The modular Nipype-based architecture enables efficient workflow management and supports parallel processing capabilities for large-scale applications.

The preprocessing module successfully handles the core FFR processing steps, including channel re-referencing, filtering, epoching based on BIDS event files, and generation of averaged evoked responses. Testing on example datasets confirmed that the pipeline produces expected FFR waveforms with clear stimulus-locked activity. Analysis functions, including power computation, signal-to-baseline RMS calculation, and pitch-tracking fidelity via autocorrelation, generate appropriate output metrics and successfully characterize fundamental frequency encoding in the FFR response.

FFRPREP generates automated HTML reports that provide comprehensive documentation of processing steps and analysis outcomes. Reports include interactive visualizations such as waveform plots, spectrograms, power spectra, and pitch-tracking results that support quality assessment. Provenance tracking documents all processing parameters and software versions, supporting reproducibility.

FFRPREP is available as an open-source Python package on GitHub with documentation hosted on GitHub Pages. Automated testing through continuous integration ensures code reliability. Docker and Singularity containers are automatically built and distributed through GitHub Actions, enabling users to run FFRPREP without managing complex software dependencies. The software has been successfully deployed on both high-performance computing clusters and local workstations.

Conclusion

The FFR is a well-used auditory research and clinical-evoked response that characterizes the fidelity of early auditory processing in the human brain. However, the lack of standardized data structures, processing and analysis methods, and reporting hinder the interpretation of results across studies, which frequently implement different methods and report different metrics. We are developing FFRPREP to standardize each of these steps in order to encourage new investigations using community-defined best practices, to augment across-study interpretation of findings, and to support wider use of the FFR as a neurobiologically and clinically relevant tool for characterizing the auditory system.

FFRPREP adheres to open science best practices, including data standardization (through BIDS formatting), reproducibility (through containerization and software transparency), and accessibility. Instead of reinventing specific methods in-house, we are building FFRPREP on well-supported and well-documented open-source packages such as MNE-Python and Nipype.

Future enhancements to FFRPREP will support additional user-defined processing options, such as an array of data filtering options, dimensionality reduction-based artifact identification and removal. Analysis enhancements will focus on FFR-specific analysis measures, including polarity-added and polarity-subtracted pipelines for insights into acoustic envelope features and temporal fine structure, respectively. We are also continuing to build our documentation in order to support FFRPREP utility for a wider range of existing and new FFR datasets.
