Introduction

Almost ten years ago, a survey from Nature1 showed that among 1576 researchers, over 70% did not succeed in reproducing their colleague’s findings based on the provided result and method descriptions. This highlighted a growing reproducibility crisis in research. Over the past years, this raised awareness on the need to adopt better sharing practices so that results can be replicated and therefore trusted. In the same vein, the FAIR principles2 were created, consisting of a set of guidelines to improve the Findability, Accessibility, Interoperability, and Reuse of digital assets.


Later, the Neuroimaging Analysis Replication and Prediction Study (NARPS)3 raised additional concerns. In this paper, Botvinik-Nezer and colleagues showed how different analyses performed on the same data to answer the same research questions could lead to different findings. Even if this study made it mandatory for all participating teams to share their output data as well as a description of the analytical workflows based on the COBIDAS guidelines, reproducing its results is non-trivial, leading to a limited understanding of the observed variability. As for this study, there is still a lot of open research questions regarding analytical variability that could benefit from better method descriptions.

Retrospective provenance – i.e. the description of steps that were applied to produce data – can help both in making research findings more reproducible, and in comparing data generation workflows to understand the variability they induce. In neuroimaging, the Brain Imaging Data Structure (BIDS)4 emerged as a key standard to organize, store, and share brain imaging associated data, code, documentation and other digital artifacts. As such, it aims at steering researchers toward the FAIR principles. The goal of the presented work is to introduce a BIDS Extension Proposal (BEP) to enrich the BIDS specification with provenance features.

Methods

Retrospective provenance aims at describing the list of steps (also called activities in the following) that generated a dataset. It takes the form of metadata about objects such as files, datasets, software packages, software environments, and activities. It also describes the relations that exist between these objects, e.g. the fact that an activity used a file as input and generated another file using a given piece of software. As a result, provenance can be represented as a directed acyclic graph (DAG, see Fig.1 for an example).

W3C Prov5 is a standard to describe provenance as a graph in the Resource Description Framework (RDF). Although RDF is a cornerstone for the information technologies domain, it is not well known inside the neuroimaging community. Therefore we rely on the following principles so that the proposed provenance description is better suited for BIDS while remaining compatible with RDF through W3C Prov.

Use BIDS features - BIDS already provides means for metadata storage with JSON fields identified by human-readable keys. We use these to hold provenance information related to files and datasets. We also introduce additional JSON files and attributes to provide detailed provenance information for other objects. As a result, provenance metadata is stored consistently alongside the data it describes. This metadata can later be easily aggregated into a single JSON-LD file so that it is correctly encoded as an RDF graph.

Foster adoption - Terms from the W3C Prov ontology were adapted through a JSON-LD context so that they correspond to how BIDS -and more broadly the neuroimaging community- describe objects. The proposed way to describe provenance is easily readable by humans, and can be computer generated or edited manually. One goal being to encourage its adoption by neuroscientists, researchers and software developers. Figure 2b shows JSON provenance metadata excerpts.

Allow flexibility - Provenance can be described at different levels of granularity. Our work allows describing a variety of data transformations in a flexible way, e.g. from high perspective relations between datasets to detailed workflows involving individual references to files, parameters, versioned software, etc.

Results

This work takes the form of a BIDS Extension Proposal, following the contribution guidelines and processes required by BIDS. We demonstrate that common data processing can be efficiently and precisely described using provenance metadata inside BIDS datasets. Figure 2a identifies files where provenance metadata can be stored inside the directory tree of a BIDS dataset.  Figure 2b shows JSON provenance metadata excerpts.

The BEP workflow led to several deliverables : 1. a specification update and 2. a set of example datasets (DICOM to NIfTI conversion with dcm2niix; DICOM to NIfTI conversion with heudiconv; fMRI preprocessing with fMRIPrep; fMRI preprocessing with SPM; Manual brain segmentation) that illustrate how the new features adapt to different use-cases. This includes manual annotation such as manually performed brain segmentations; transformations made by custom software like scripts; use of off-the-shelf software packages, libraries or workflows to process data; and data conversion from raw to standard format and organization. These examples also showed that provenance in BIDS can be described at different levels of granularity and completeness, and they act as guidelines for both human and computer written metadata.

Finally, as part of the BIDS contribution process, changes to the BIDS specification are submitted to community review before they are merged into the standard.

Conclusion

We conducted a collaborative work to integrate provenance of files and datasets inside the BIDS standard for brain imaging. Our contribution to this specification allows for flexible descriptions of data transformations, processing, and analyses. The metadata is human readable as well as computer actionable, while remaining compatible with the W3C Prov standard, helping neuroscientists and researchers deeply understand and analyze the steps leading to a given dataset. A set of examples was also created to demonstrate that provenance metadata in BIDS can adapt to different workflows that are commonly used in the neuroimaging community.
