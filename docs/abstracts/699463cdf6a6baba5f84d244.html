Introduction

The field of neuroimaging has witnessed an exponential increase in data production and availability, fueled by technical advances that have enabled large-scale data collection, as well as by changes in policies and funding initiatives that support open data-sharing programs. As the number of openly available datasets grows larger, the need for efficient, standardized, and flexible tools to index, inspect, and fetch neuroimaging data is becoming a pressing need. OpenNeuro is a popular data hosting service in neuroimaging research^1; it allows to share publicly neuroimaging data stored following the Brain Imaging Data Structure (BIDS) standard.^2 Although tools such as bids2table (https://childmindresearch.github.io/bids2table/bids2table.html) or Neurobagel query enable interrogating BIDS datasets (including those on OpenNeuro) and the associated metadata,^3 researchers that require using a subset of one or multiple datasets stored in data repositories typically need to fetch the entire dataset, and to use dedicated tools to interrogate and select the relevant data, hindering interoperability and scalability. Furthermore, existing tools to interrogate BIDS datasets only enable interrogating the metadata, and miss other features that can only be obtained by inspecting the actual volumetric data. Conversely, command-line tools allowing to fetch datasets from remote servers (e.g., Cohort Creator) do not provide data inspection or metadata-based filtering capabilities.^4 Thus, a tool to efficiently interrogate and filter neuroimaging data hosted on public repositories is missing.

We present NiQuery, a principled, open-source Python library designed to address these challenges by providing a robust framework for querying neuroimaging datasets, inspecting metadata, performing subset selection, and aggregating results. NiQuery seeks to facilitate reproducible research by enabling transparent access to the content of neuroimaging datasets, including volume-specific metadata.

Methods

NiQuery is engineered for ease-of-use, flexibility and extensibility. The core principles guiding its development include:

  • Modularity: NiQuery comprises a suite of independent modules, each responsible for a specific aspect of dataset querying or analysis (e.g., indexing the remote dataset hosting repository contents, collecting per-dataset files, etc.).
  • Metadata extraction: NiQuery emphasizes metadata-driven analysis, offering tools to extract, parse, and select data based on metadata from imaging file-level sources (primarily, NIfTI files).
  • Extensibility: NiQuery can be adapted to filter data based on custom criteria.
  • Composability: NiQuery provides a way to create new datasets by aggregating multiple datasets, potentially leveraging the standardized folder structure and metadata conventions offered by standards like BIDS.

NiQuery allows to perform the following set of actions:

  • Index: Retrieve available neuroimaging datasets and snapshot information.
  • Collect: Gather per-dataset file listings.
  • Analyze: Extract features from collected files.
  • Select: Choose datasets that satisfy specific constraints.
  • Aggregate: Create a new DataLad dataset from the selected datasets.^5

Figure 1a illustrates the core workflow that governs the dataset selection and aggregation in NiQuery. NiQuery leverages the GraphQL (https://graphql.org/learn/) data query language to index datasets hosted by a remote server. NiQuery performs HTTP (Hypertext Transfer Protocol) requests to the server to index the datasets and relevant files. It features an exponential backoff strategy to delay posting new requests in case of server-side errors up to a given number of attempts.

In order to interrogate data features for subset selection, NiQuery retrieves only the NIfTI header data of the relevant files in the HTTP response stream (Figure 1b), thus avoiding the need to fetch entire, storage-intensive neuroimaging data files.

NiQuery is implemented in Python and parallelizes operations to improve efficiency. It features an intuitive interface: it provides a niquery overarching command for all command-line interface (CLI) operations, and exposes a set of subcommands (e.g., index, collect) to easily perform the above actions. It is exhaustively tested through unit and integration tests that are run through continuous integration to ensure code reliability. The codebase and API are fully documented, complemented by a comprehensive user guide, setting clear expectations for developers and end-users. Additionally, all CLI commands provide context-sensitive help through a standard --help flag, allowing users to quickly access usage instructions and option descriptions. NiQuery logs relevant operational information, including failed query attempts, to facilitate subsequent inspection.

In this work, we demonstrate the capabilities of NiQuery by querying OpenNeuro. Specifically, we employ NiQuery to index all available blood-oxygen-level-dependent (BOLD) functional magnetic resonance imaging (fMRI) datasets acquired on human subjects. We identify the relevant list of volumetric data files, and characterize their content in terms of the number of BOLD timepoints they contain. Finally, we seek to create a new superset of 4000 total BOLD runs based on the following arbitrary constraints: (i) No single dataset will contribute more than 5% of the total number of runs; and (ii) each BOLD run must have 300–1200 timepoints. We employ the default parameters for the exponential backoff strategy, i.e., 5 attempts at maximum with a 1.5 s delay. Experiments are performed on a desktop machine featuring a CPU clock at 3.30 GHz, 6-core, 12-thread processor, 32 GB of RAM, and connected through a 2.5 Gbps link.

Results

Indexing all OpenNeuro datasets (1549 datasets at the time of writing this abstract) takes a little over 1 minute. Listing all modality-specific NIfTI files across datasets is the slowest process, and may take several hours to complete: for the fMRI BOLD query in this experiment, it takes around 10 hours to list all files from over 550 relevant datasets. The time required to list all files is influenced by (i) the number of files that each queried dataset contains, and (ii) the number of attempts to obtain a successful response from the server following the parameters of the exponential backoff strategy. Once all files have been listed, NiQuery takes in the order of several minutes (around 20 minutes in our experiment) to extract the metadata from the listed NIfTI files of interest (over 130 000 fMRI BOLD files). Finally, NiQuery provides the list of the dataset files that comply with the required criteria in less than 1 second.

NiQuery offers gains in automation and reproducibility: leveraging its automated data interrogation abilities, it enables automated dataset selection. Thus, researchers can minimize manual intervention, reduce errors, and ensure that analyses are tailored to available data.

Conclusion

In summary, NiQuery is a principled, easy-to-use, and robust tool for agile exploration, subset selection and reuse of open access neuroimaging data hosted on OpenNeuro for targeted analysis and hypothesis testing. NiQuery offers an easy-to-use command-line interface for efficient volume metadata interrogation and retrieval of neuroimaging datasets that comply a set of pre-defined criteria. Its adoption facilitates transparent reporting, and streamlined workflows, addressing a need for research data subset selection and hypothesis testing in neuroimaging. The key contributions of NiQuery include:

  • Standardized dataset discovery and interrogation: By providing a unified interface for dataset interrogation, NiQuery enables transparent and reproducible data selection.
  • Automated volume inspection: Fast extraction and convenient representation of volume metadata support rigorous analyses and facilitate relevant data identification.
  • Dataset aggregation: By offering dataset aggregation capabilities, it reduces manual intervention, improves reliability, and accelerates research.

Future work includes adding the ability to query other modality data, local datasets or other remote repositories supporting the GraphQL syntax, expanding the dataset selection criteria, and adding reporting and visualization capabilities summarizing dataset structure and metadata distributions.

NiQuery is released under an Apache License, Version 2.0 as a Python package (https://pypi.org/project/niquery/) and hosted at the https://github.com/nipreps/niquery/ address.
