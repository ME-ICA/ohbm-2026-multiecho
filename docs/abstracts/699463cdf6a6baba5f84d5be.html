Introduction

The design of brain image analysis toolkits relies on the availability of libraries that that facilitate development, testing and dissemination. Popular open-source libraries for the analysis of DICOM and NIfTI brain images exist in Python and MatLab, where manipulation of pixel data is made easy thanks to flexible data types and many built-in mathematical operations.

Although most of the libraries above rely on underlying C++ libraries for their speed and efficiency, there are surprisingly few libraries that work directly in C++, especially when it comes to exposing the pixel data in data types that allow easy manipulation. 

The library for Computer Analysis of Brain Image Statistics (CAnaBIS) allows the C++ programmer to load DICOM and NIfTI images and access them via the XTensor libraries, which are built around flexible-dimensionality numerical arrays in the style of NumPy in Python, and to collect the arrays resulting from their processing steps to store them in common file formats.

This library interacts with many other open-source projects:

  • collecting dependencies and organising the build is done by CMake [1]
  • DICOM access uses DCMTK [2], in combination with in-house code for accessing Siemens legacy (MOSAIC) files
  • NIfTI I/O relies on the NIfTI C libraries [3] with compression support using GZip
  • The JSON libraries of Niels Lohmann [4] to write BIDS [5] sidecars and access DICOM headers
  • The XTensor libraries [6] with support for OpenBLAS, FFTW, Image I/O

The full CAnaBIS library with its supporting software will form the basis for the Brain Image Statistics  software [7], command-line and GUI-based programs for image processing and image analysis methods development.

Methods

The library has a class hierarchy that is based on the nested file types they represent. The base class is bis::bisimage, which holds the pixel data in a std::vector of the given pixel data type, and an adaptor of this vector to interface as an xt::xarray, a C++ equivalent of the NumPy ndarray in Python. This facilitates the export of the pixel data to xtensor containers after reading from file, and import of these containers to write to file. This functionality is comparable to NiBabel in Python.

The bis:bisnifti class inherits from the base class and has extra functionality for NIfTI file I/O, such as reading from and writing to files, changing the pixel data type, editing header fields, etc. Inheriting from it is the bis::bisbids class, which supports the BIDS format consisting of a NIfTI image and an accompanying JSON sidecar. The most specific class is bis::bisdicom, which inherits from bis:bisbids and can be used to read DICOMS and populate a BIDS image/sidecar pair. Extensive header information such as Siemens CSA and MrPhoenixProtocol fields, may be saved in separate JSON files. 

Once the pixel data have been exported as an xarray data type, it is possible to apply different mathematical and technical operations:

  1. xtensor-specific data manipulation includes matrix and vector mathematics, array slicing, random value generation and statistics, shape and index reorganisation
  2. xtensor-blas functionality: this extension gives xtensor objects access to the BLAS and LAPACK libraries that are installed on the system, for doing fast and efficient linear algebra on large matrices
  3. xtensor-fftw links xtensor objects to the fftw3 library, with highly optimised implementations for the Fourier tansform
  4. xtensor-io uses the OpenImageIO system to support input from and export to a large number of common file formats for storing signals and images

If the processing steps on the data are done with xtensor-based data types, or brought back into the xtensor format, data can be imported back into one of the data types described above - in practice it will often be the bis::bisimage class for writing a NIfTI image.

This part of the workflow, also provided by CAnaBIS objects, is similar again to the role of NiBabel in Python neuroimaging workflows.

Results

We demonstrate a code block in which:

A. Basic 2-dimensional, 3-dimensional and 4-dimensional vectors and matrices (the dimensionality of most medical images) are handled in the xtensor data types;

B. A for-dimensional bis:bisimage object is created and manipulated. These are operations on the object's adaptor, which in turn changes the data values in the underlying std::vector that contains its data.

C. A NIfTI image is read from file, saved in a different pixel data type, exported to an xt:xarray object, transformed to the frequency domain and back, imported and saved again as a NIfTI file.

D. Several DICOM files from Philips and Siemens scanners are read and saved as NIfTI files with BIDS sidecars. Siemens scans include files in the MOSAIC scans whose extensive protocol data are extracted and stored as JSON files.

Conclusion

We have integrated the functionality of the C++ xtensor arrays to the CAnaBIS library, enabling workflow development with the ease of Python and the speed and efficiency of C++. This library will form the basis of a command-line image processing program (ComBIS) and a GUI-based application (BISkits).
